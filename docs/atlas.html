01What this isŠta je ovo

A local, single-user tool that turns AI coding sessions into a searchable knowledge vault and feeds it back to the AI.Lokalni alat za jednog korisnika koji AI coding sesije pretvara u pretraživ vault znanja i vraća ga nazad AI-ju.

vir reads the transcripts Claude Code leaves on your disk and turns the useful ones into short notes of four kinds: pattern, gotcha, decision, tool. It writes them as Markdown into your Obsidian vault and keeps its bookkeeping in one SQLite file. Claude Code gets the knowledge back through a block in your CLAUDE.md files and through an MCP server (a tool Claude Code can call mid-session).

vir čita transkripte koje Claude Code ostavlja na disku i korisne pretvara u kratke beleške četiri vrste: pattern, gotcha, decision, tool. Upisuje ih kao Markdown u tvoj Obsidian vault, a svoje evidencije drži u jednom SQLite fajlu. Claude Code dobija znanje nazad kroz blok u tvojim CLAUDE.md fajlovima i kroz MCP server (tool koji Claude Code može da pozove usred sesije).

Claude Codewrites .jsonl transcriptspiše .jsonl transkripte
vir rundaemon, every few hoursdaemon, na par sati
LLM providerAnthropic, Kie or claude CLIAnthropic, Kie ili claude CLI
Vault + SQLiteVault + SQLitenotes, vectors, statebeleške, vektori, state
MCP + CLAUDE.mdknowledge goes backznanje se vraća

…and the next Claude Code session starts with it. No server, no accounts: everything is on your machine.…i sledeća Claude Code sesija kreće sa njim. Nema servera ni naloga: sve je na tvojoj mašini.

02How it worksKako radi

One engine folder, one command folder, one file with all the SQL; the rest are satellites.Jedan folder je motor, jedan su komande, jedan fajl drži sav SQL; ostalo su sateliti.

The pipeline — the enginePipeline — motor

Finds transcripts, drops the ones it must not pay for, cleans the rest, asks the model for a note, writes it. One shared function does the per-session work for both normal runs and retries.

Nalazi transkripte, izbacuje one za koje ne sme da plati, čisti ostale, traži od modela belešku i upisuje je. Jedna zajednička funkcija radi posao po sesiji i za obične run-ove i za retry.

Search — meaning first, keywords as backupSearch — prvo značenje, ključne reči kao rezerva

Each note has a vector (numbers that capture its meaning). A question is compared against notes made by the same model. Approved notes get a small boost. If nothing matches, plain keyword search (TF-IDF) takes over.

Svaka beleška ima vektor (brojevi koji hvataju njeno značenje). Pitanje se poredi sa beleškama koje je napravio isti model. Odobrene beleške dobijaju mali boost. Ako ništa ne odgovara, uskače obična pretraga po rečima (TF-IDF).

Flow 2 · core

The scheduled run: transcripts become notesZakazani run: transkripti postaju beleške

Why this matters: this loop spends money on every session it lets through, and its rows decide whether a note is ever visible.

Zašto je bitno: ova petlja troši novac na svaku sesiju koju pusti, a njeni redovi odlučuju da li se beleška ikad vidi.

  1. The scheduler starts vir run --daemon every few hours (default 3).Scheduler pokreće vir run --daemon na par sati (default 3).
  2. vir takes the lock so no other run can work at the same time.vir uzima lock da nijedan drugi run ne radi u isto vreme.Before 0.23.2 two runs could both "win" the lock and pay twice.Pre 0.23.2 dva run-a su mogla oba da „dobiju" lock i plate duplo.
  3. It hashes every transcript and drops what it must never pay for: agent transcripts, excluded or undecided projects, done work, demoted notes, sessions that failed three times.Hešira svaki transkript i izbacuje ono za šta nikad ne sme da plati: agent transkripte, isključene ili neodlučene projekte, gotov posao, spuštene beleške, sesije koje su pale tri puta.A paid step placed before a free filter wastes money on every run.Plaćen korak pre besplatnog filtera baca novac na svaki run.
  4. One tiny test call checks the provider before anything is spent.Jedan mali test poziv proverava providera pre nego što se išta potroši.
  5. For each session it strips tool noise and secrets, trims a huge transcript to fit, then asks the model to classify it and write a note and a title.Za svaku sesiju skida šum od tool-ova i tajne, skraćuje ogroman transkript da stane, pa traži od modela da je klasifikuje i napiše belešku i naslov.A note scored too low is not written; if one already existed, it is kept.Beleška sa preniskom ocenom se ne piše; ako je već postojala, ostaje.
  6. The note goes to the vault; its row and vector go to SQLite.Beleška ide u vault; njen red i vektor idu u SQLite.Before 0.24.0 the vector was stored before the row existed, so every new note was embedded twice.Pre 0.24.0 vektor se upisivao pre nego što red postoji, pa je svaka nova beleška embed-ovana dvaput.
  7. After the loop: project summaries, articles, PDFs, and a sweep that fills in missing vectors.Posle petlje: sažeci projekata, članci, PDF-ovi i sweep koji popunjava vektore koji fale.

Flow 4 · money

What a call costs, and how spend is guardedKoliko poziv košta i kako se čuva trošak

Why this matters: the provider bills real money; the log is the only record vir keeps.

Zašto je bitno: provider naplaćuje pravi novac; log je jedini zapis koji vir čuva.

  3. Subscription calls and unpriced models are logged as unknown, never $0.Pozivi preko pretplate i modeli bez cene loguju se kao nepoznato, nikad $0.
  4. vir cost totals the log and lists quota and unpriced calls apart.vir cost sabira log i posebno prikazuje quota i pozive bez cene.
  5. Guards: a cost prompt on big runs, a 25-session cap on the subscription, confirmations on audit, dedupe, lint, compose and reconcile.Zaštite: cost prompt na velikim run-ovima, limit od 25 sesija na pretplati, potvrde na audit, dedupe, lint, compose i reconcile.Some paths still spend without asking — see "What's done".Neke putanje i dalje troše bez pitanja — vidi „Šta je gotovo".

Flow 5 · failure

Provider down, quota wall, a failing sessionProvider pao, quota zid, sesija koja pada

Why this matters: Claude Code deletes old transcripts after about 30 days, so a session never retried in time is lost.

Zašto je bitno: Claude Code briše stare transkripte posle oko 30 dana, pa je sesija koja se ne ponovi na vreme izgubljena.

  1. If the provider is down, the probe fails once; vir records it, notifies you, and stops.Ako provider ne radi, probe padne jednom; vir to zapiše, javi ti i stane.
  2. If the subscription quota runs out mid-run, vir stops and records nothing, so the rest is simply new next time.Ako quota istekne usred run-a, vir stane i ništa ne upiše, pa je ostatak sledeći put prosto nov.Before 0.23.1, articles and PDFs hit by the wall were lost for good.Pre 0.23.1 članci i PDF-ovi koje udari zid bili su zauvek izgubljeni.
  3. A single failing session gets an error and an attempt counter; after three it is parked.Sesija koja pada dobija grešku i brojač pokušaja; posle tri se parkira.
  4. vir reconcile retries failures, but only what vir run would still process.vir reconcile ponavlja pale, ali samo ono što bi vir run i dalje obradio.
  5. vir doctor shows all of it.vir doctor prikazuje sve to.

APP-ATLAS.md §7

07Important to know if asked in a job interview

Twelve likely questions, answered from facts in the atlas — weaknesses included.Dvanaest verovatnih pitanja, odgovoreno činjenicama iz atlasa — uključujući slabosti.

"Walk me through the architecture."„Provedi me kroz arhitekturu."

vir is a local command-line tool, not a service. It reads the transcript files Claude Code leaves in my home directory, runs the useful ones through a model to make short typed notes, and writes them as Markdown into my Obsidian vault. State lives in one SQLite file: what was processed, the vectors for search, and what was rejected or demoted. A launchd job runs it every few hours. The same binary also runs as an MCP server that Claude Code starts, so the agent can search the notes mid-session. No network listener and no database server; that was the point.

vir je lokalni command-line alat, ne servis. Čita transkripte koje Claude Code ostavlja u home folderu, korisne pušta kroz model da napravi kratke tipizirane beleške i upisuje ih kao Markdown u moj Obsidian vault. State je u jednom SQLite fajlu: šta je obrađeno, vektori za pretragu, i šta je odbijeno ili spušteno. launchd job ga pokreće na par sati. Isti binary radi i kao MCP server koji Claude Code pokreće, da agent može da pretražuje beleške usred sesije. Nema network listener-a ni database servera; to je i bila poenta.

Testing: whether you can describe boundaries and data flow.Proverava: da li umeš da opišeš granice i tok podataka.

Follow-up: "Why not a web service?" — It is single-user and the data is personal; a service adds hosting, auth and privacy problems for no gain.Sledeće pitanje: „Zašto ne web servis?" — Za jednog je korisnika i podaci su lični; servis dodaje hosting, auth i privatnost bez koristi.

"Why SQLite and plain files?"„Zašto SQLite i obični fajlovi?"

The notes are the product and I edit them in Obsidian, so they must be files. SQLite holds what files cannot: content hashes so I know what was already paid for, the vectors, retry counters and review overlays. It needs no server, and WAL mode lets the read-only MCP server read while a run writes. Migrations only ever add columns, because the daemon and the MCP server open old databases.

Beleške su proizvod i menjam ih u Obsidian-u, pa moraju biti fajlovi. SQLite drži ono što fajlovi ne mogu: hash-eve da znam šta je već plaćeno, vektore, brojače pokušaja i review overlay-e. Ne treba mu server, a WAL režim pušta read-only MCP server da čita dok run piše. Migracije samo dodaju kolone, jer daemon i MCP server otvaraju stare baze.

Testing: whether storage was chosen or just defaulted.Proverava: da li je storage izabran ili samo default.

Follow-up: "Where does it break?" — Sessions are matched with LIKE '%/<id>.jsonl', a full table scan; fine for thousands of rows, not millions.Sledeće pitanje: „Gde puca?" — Sesije se nalaze sa LIKE '%/<id>.jsonl', što je full table scan; ok za hiljade redova, ne za milione.

"How do you avoid paying twice for the same work?"„Kako izbegavaš da platiš dvaput isti posao?"

Every transcript is hashed. A matching stored hash means done, so the next run skips it for free. All the cheap filters run before the first paid call: project decisions, agent transcripts, demoted notes, sessions that failed three times. A lock file stops two runs overlapping, and big batches show a cost estimate first.

Svaki transkript se hešira. Isti upisan hash znači gotovo, pa ga sledeći run besplatno preskače. Svi jeftini filteri idu pre prvog plaćenog poziva: odluke o projektima, agent transkripti, spuštene beleške, sesije koje su pale tri puta. Lock fajl sprečava preklapanje run-ova, a veliki batch-evi prvo pokažu procenu cene.

Testing: idempotency — twice has the same effect as once.Proverava: idempotency — dvaput ima isti efekat kao jednom.

Follow-up: "And a failed call?" — It keeps the old hash and bumps an attempt counter: retried, but at most three times.Sledeće pitanje: „A poziv koji padne?" — Zadržava stari hash i povećava brojač: ponavlja se, ali najviše tri puta.

"What was the hardest bug?"„Koji ti je bio najteži bug?"

The lock. The first version checked whether the lock file existed and then wrote it — two steps, so two processes starting together could both win. I switched to an exclusive create and raced eight real processes against it. A fresh lock now had one winner, but a stale lock left by a crash still gave about three winners per trial: one process judged it stale, another replaced it, and the first deleted the replacement. A second guard file, so only one process may remove a stale lock, fixed it: twenty trials, one winner each.

Lock. Prva verzija je proveravala da li lock fajl postoji pa ga upisivala — dva koraka, pa su dva procesa koja krenu zajedno mogla oba da pobede. Prešao sam na ekskluzivno pravljenje i pustio osam pravih procesa da se trkaju. Svež lock je sad imao jednog pobednika, ali stale lock posle pada i dalje je davao oko tri pobednika po pokušaju: jedan proces ga proceni kao stale, drugi ga zameni, a prvi obriše zamenu. Rešio je drugi guard fajl, da samo jedan proces sme da briše stale lock: dvadeset pokušaja, po jedan pobednik.

Testing: debugging method, and honesty when the first fix was not enough.Proverava: metod debug-ovanja i iskrenost kad prvi fix nije dovoljan.

Follow-up: "Why not a database lock?" — Some lock holders never open the database, and a pidfile survives crashes in a way that is easy to inspect.Sledeće pitanje: „Zašto ne database lock?" — Neki koji drže lock nikad ne otvaraju bazu, a pidfile preživi pad i lako se pregleda.

"How does search work?"„Kako radi pretraga?"

Every note gets a vector from a local embedding model, Ollama or a bundled fastembed model. A question is embedded the same way and compared by cosine similarity, but only with vectors from the same model. Approved notes get a fixed boost, and MMR keeps the results from being five near-copies. If no vector matches, it falls back to TF-IDF keyword search over the files.

Svaka beleška dobija vektor iz lokalnog embedding modela, Ollama ili ugrađenog fastembed-a. Pitanje se embed-uje isto i poredi preko cosine similarity, ali samo sa vektorima istog modela. Odobrene beleške dobijaju fiksni boost, a MMR sprečava da rezultati budu pet skoro-kopija. Ako nijedan vektor ne odgovara, prelazi na TF-IDF pretragu po fajlovima.

Testing: whether you understand embeddings beyond the buzzword.Proverava: da li razumeš embedding-e dalje od buzzword-a.

Follow-up: "Is the boost principled?" — No: a flat +0.2 nudges cosine scores but dominates the much smaller TF-IDF scores.Sledeće pitanje: „Da li je boost promišljen?" — Ne: fiksnih +0,2 malo pomera cosine skorove, ali nadjača mnogo manje TF-IDF skorove.

"How do you keep secrets out of the notes?"„Kako držiš tajne van beleški?"

Before anything reaches a provider or the database, a scrubber masks API keys, bearer tokens, emails and home paths, and a tool filter removes big tool outputs. It happens in one shared function, so the run and the retry path cannot drift apart. The config file with my keys is written owner-only from the first byte.

Pre nego što išta stigne do providera ili baze, scrubber maskira API ključeve, bearer tokene, mejlove i home putanje, a tool filter skida velike tool output-e. To je u jednoj zajedničkoj funkciji, pa run i retry ne mogu da se raziđu. Config fajl sa ključevima se od prvog bajta piše tako da ga čita samo vlasnik.

Testing: security posture on a tool that reads private data.Proverava: bezbednost alata koji čita privatne podatke.

Follow-up: "Is the scrubber complete?" — No; it is pattern-based, so an unusual secret format gets through.Sledeće pitanje: „Da li je scrubber kompletan?" — Ne; radi na pattern-ima, pa neobičan format tajne prođe.

"What happens when the AI provider is down?"„Šta se desi kad AI provider ne radi?"

One cheap probe runs before the loop. If it fails, vir records a marker, sends a notification and stops: one clear failure instead of hundreds of failed sessions. If the subscription quota runs out mid-run, it stops without recording anything, so nothing counts as a failure.

Pre petlje ide jedan jeftin probe. Ako padne, vir upiše marker, pošalje notifikaciju i stane: jedan jasan pad umesto stotina palih sesija. Ako quota istekne usred run-a, staje bez upisa, pa se ništa ne računa kao pad.

Testing: failure isolation.Proverava: izolaciju grešaka.

Follow-up: "And one bad session?" — An error row and an attempt counter; after three it is parked and only vir reconcile --force retries it.Sledeće pitanje: „A jedna loša sesija?" — Red sa greškom i brojač; posle tri se parkira i samo vir reconcile --force je ponavlja.

"Where does it stop scaling?"„Gde prestaje da skalira?"

Every run hashes every transcript in full; with a few thousand files that is seconds, but it grows linearly. Search loads every vector and compares them in memory, which is fine for a personal vault of a few thousand notes. Both are deliberate: it is a personal tool.

Svaki run hešira ceo svaki transkript; sa par hiljada fajlova to su sekunde, ali raste linearno. Pretraga učitava sve vektore i poredi ih u memoriji, što je ok za lični vault od par hiljada beleški. Oba su namerna: ovo je lični alat.

Testing: knowing your limits.Proverava: da znaš svoje granice.

Follow-up: "What would you change first?" — Skip unchanged files by modification time before hashing.Sledeće pitanje: „Šta bi prvo menjao?" — Preskočio bih nepromenjene fajlove po vremenu izmene pre heširanja.

"What trade-off did you accept on purpose?"„Koji kompromis si svesno prihvatio?"

Notes are files I can edit, so some state lives in two places: approval only in the note's frontmatter, rejection in both the file's location and the database. That costs a sync step on every run, but keeps Obsidian the real interface.

Beleške su fajlovi koje mogu da menjam, pa je deo state-a na dva mesta: odobrenje samo u frontmatter-u beleške, odbijanje i u lokaciji fajla i u bazi. To košta sync korak na svakom run-u, ali Obsidian ostaje pravi interfejs.

Testing: whether you know the cost of your choices.Proverava: da li znaš cenu svojih izbora.

Follow-up: "Did it bite you?" — Yes: rejected notes kept serving from the database until a rejected_at column was added.Sledeće pitanje: „Da li te je ujelo?" — Da: odbijene beleške su i dalje služile iz baze dok nije dodata kolona rejected_at.

"How is it tested?"„Kako je testirano?"

About 1,070 Vitest tests next to the code, run against a temporary home directory so they never touch real data. Recent fixes were written test-first against a real SQLite file instead of mocks, because the mocked tests had hidden ordering bugs between writing a note and recording it. CI also type-checks the tests.

Oko 1.070 Vitest testova pored koda, pokrenutih nad privremenim home folderom da nikad ne diraju prave podatke. Skorašnji fix-evi su pisani test-first nad pravim SQLite fajlom umesto mock-ova, jer su mock testovi krili bug-ove u redosledu između upisa beleške i upisa reda. CI takođe type-check-uje testove.

Testing: whether the tests caught real bugs.Proverava: da li su testovi uhvatili prave bug-ove.

Follow-up: "What is untested?" — The MCP request handlers, the CLI wiring, and the Linux scheduler.Sledeće pitanje: „Šta nije testirano?" — MCP handler-i, CLI wiring i Linux scheduler.

"What is genuinely weak?"„Šta je stvarno slabo?"

The Linux scheduler is barely tested, and its cron fallback can overwrite a user's crontab if reading it fails. vir summarize on single projects ignores --dry-run, so a "dry run" makes real calls. And the agent-facing CLAUDE.md describes an older version, so it misleads future AI sessions.

Linux scheduler je jedva testiran, a njegov cron fallback može da pregazi korisnikov crontab ako čitanje padne. vir summarize za pojedinačne projekte ignoriše --dry-run, pa „dry run" pravi prave pozive. A CLAUDE.md za agenta opisuje stariju verziju, pa zavarava buduće AI sesije.

Testing: honesty.Proverava: iskrenost.

Follow-up: "Why not fixed?" — They were found while writing this atlas and are listed as findings.Sledeće pitanje: „Zašto nije rešeno?" — Nađeni su dok se pisao ovaj atlas i navedeni su kao nalazi.

"How do you control cost?"„Kako kontrolišeš trošak?"

Every model call goes through one function that logs tokens and an estimated cost. Subscription calls and models with no known price are logged as unknown rather than zero, so totals are never quietly wrong. Big runs show an estimate first, and a subscription run is capped at 25 sessions.

Svaki poziv modela ide kroz jednu funkciju koja loguje tokene i procenjenu cenu. Pozivi preko pretplate i modeli bez poznate cene loguju se kao nepoznato, ne nula, pa zbirovi nikad nisu tiho pogrešni. Veliki run-ovi prvo pokažu procenu, a run na pretplati je ograničen na 25 sesija.

Testing: operational maturity.Proverava: operativnu zrelost.

Follow-up: "Any spend without a prompt?" — Yes: small runs, vir calibrate, and the agent's vir_query unless it opts out.Sledeće pitanje: „Ima li troška bez pitanja?" — Ima: mali run-ovi, vir calibrate, i agentov vir_query osim ako odustane.
